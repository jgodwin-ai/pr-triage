# PR Triage Bot — Phase 1.7: Virtual Stacked PRs

**Status:** Design approved — 2026-05-06
**Spec for:** Phase 1.7 implementation plan (to follow)

## Goal

Decompose any PR into a **virtual stack** — one level per commit — and let the reviewer walk the stack bottom-up, getting the full triaging pipeline applied to each commit's diff relative to its parent. The stack is rendered as a slim timeline rail in the left panel. No real GitHub branches or PRs are created; the entire stack lives in our app's data model and UI.

The reviewer's mental model: "start at the bottom, climb the stack one commit at a time, and at each step see exactly what changed and what to verify."

## Non-Goals

- Creating real stacked GitHub PRs / branches.
- Multi-PR stacks (a graph of related PRs targeting each other).
- Reordering, splitting, or rewriting commits from the UI.
- Adding new analysis capabilities — Phase 1.7 reuses Phase 1's three-stage pipeline as-is. Phase 2's structural analyzer can plug in later via the same per-level interface.

## Key Decisions

| # | Decision | Why |
|---|---|---|
| 1 | Virtual stack only | Real stacked PRs are operationally heavyweight and reversibility is hard. |
| 2 | One level per commit, with auto-collapsed noise | Predictable; reviewer keeps full granularity. Heuristic noise filter for fixup/wip/lockfile-only commits. |
| 3 | Incremental diffs (commit N vs N-1) | Matches the "build up understanding" framing. Final level shows only the last commit's changes. |
| 4 | Slim timeline rail (~48px) on far left + existing cluster panel | Always-visible affordance even for one-commit PRs; minimal disruption to existing UI. |
| 5 | Eager up-front pipeline, all levels in parallel | Fastest navigation. Cached by commit SHA so revisits are instant. |
| 6 | Comments anchored to commit SHA | Submitted via GitHub review API's `commit_id` field. Reviewer authors comments per-level. |

## Architecture

```
GitHub API ──┐
             ├──► commit-stack.ts ──► classify → per-level diffs
             │                              │
             │                              ▼
             │                     pipeline.ts (×N levels, parallel)
             │                              │
             ▼                              ▼
         analysis-cache (keyed by (prUrl, commitSha))
                            │
                            ▼
              GET /api/pr/:owner/:repo/:num/stack
                            │
                            ▼
                Frontend: TimelineRail + AnalysisView
                                 │
                                 ▼
            Drafts tagged with commit_id → review.ts
                                 │
                                 ▼
             GitHub PR review (per-commit inline comments)
```

## Components

### Backend

- **`backend/src/services/commit-stack.ts`** — pulls `GET /repos/{o}/{r}/pulls/{n}/commits`, computes per-commit diffs (commit N vs its parent within the PR — falls back to PR base for the first commit), returns a `StackLevel[]`.
- **`backend/src/services/noise-classifier.ts`** — pure function `classify(commit, diff): "feature" | "noise"`. Heuristics:
  - `fixup!` / `squash!` commits
  - Subject prefix `wip:` / `wip ` (case-insensitive)
  - Subject prefix `chore(deps)` or message body containing `git-bump`-style markers
  - Diffs <5 LOC ignoring lockfiles
  - Lockfile-only diffs (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock`, `poetry.lock`, `Pipfile.lock`, `go.sum`)
- **`backend/src/services/pipeline.ts`** (extended) — accepts a `(commitSha, parentSha, files[])` triple. Emits the existing `AnalysisResult`; nothing downstream changes.
- **`backend/src/services/analysis-cache.ts`** (extended) — cache key becomes `${prUrl}#${commitSha}`. Single-PR callers pass the head SHA for back-compat.
- **`backend/src/routes/analyze.ts`** — new `GET /api/pr/:owner/:repo/:num/stack` returns the stack metadata immediately and triggers per-level pipelines in parallel. Existing WebSocket emits `levelReady { sha, analysis }` and `levelError { sha, error }` events.
- **`backend/src/routes/review.ts`** (extended) — accepts `commit_id` per draft comment. GitHub's Reviews API only takes a top-level `commit_id` per review (not per-comment), so the backend groups comments by SHA and submits one review per unique SHA. A single APPROVE/REQUEST_CHANGES verdict applies to one review; the others are submitted as `COMMENT` events.

### Frontend

- **`frontend/src/components/TimelineRail.tsx`** — slim (48px) far-left rail. One node per level, oldest at the bottom. Per-node UI: status dot (analyzing / ready / error), draft-count badge, short SHA. Noise commits dimmed and grouped under a "▾ N hidden" expander.
- **`frontend/src/state/stack.ts`** — store with `levels`, `selectedSha`, `setSelected(sha)`, `levelAnalysis(sha)`. Persists `selectedSha` per PR in localStorage.
- **`frontend/src/components/AnalysisView.tsx`** (modified) — reads `selectedSha` and renders that level's analysis. Cluster sidebar, diff viewer, and right rail are unchanged — they receive a per-level `AnalysisResult`.
- **`frontend/src/components/CommentBox.tsx`** (modified) — captures `selectedSha` as `commit_id` when a draft is created. Draft store keys by `(commit_id, file, line)`.

Files explicitly *not* modified: `RightRail`, `ExecutiveSummary`, `DraftedComments`, `ChatPanel`, `DiffViewer`. They consume `AnalysisResult` and stay agnostic to the stack.

## Data Model

```ts
// backend/src/types.ts (additions)

type CommitKind = "feature" | "noise";

interface StackLevel {
  sha: string;          // full SHA — also the cache key suffix
  shortSha: string;     // first 7
  message: string;      // commit subject only
  parentSha: string;    // sha of previous level OR PR base for level 0
  kind: CommitKind;
  noiseReason?: string; // e.g. "fixup commit", "lockfile-only"
  files: string[];      // changed in this commit only
  status: "pending" | "analyzing" | "ready" | "error";
  analysis?: AnalysisResult; // existing Phase 1 type, unchanged
}

interface Stack {
  prUrl: string;
  baseSha: string;     // PR.base.sha
  headSha: string;     // PR.head.sha
  levels: StackLevel[]; // ordered oldest → newest
}

interface DraftComment {
  // existing fields...
  commitId: string;    // SHA the comment is anchored to (the level it was drafted on)
}
```

## API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/pr/:owner/:repo/:num/stack` | Returns `Stack` with `status: "analyzing"` for unfinished levels. Triggers pipelines in parallel. |
| `WS` | existing analysis socket | New event types: `levelReady { sha, analysis }`, `levelError { sha, error }`. |
| `POST` | `/api/review/submit` (existing) | Body adds `comments: { commit_id, path, line, body }[]`. Forwarded to GitHub. |

The existing `POST /api/analyze` stays as a thin wrapper that calls the stack endpoint with `levels = [headSha]` for back-compat with the single-PR flow.

## Behavior at the Edges

- **One-commit PRs.** Stack has a single feature level. Rail still renders (one dot) so the affordance is consistent.
- **All-noise PRs (rebase-only, lockfile bumps).** Rail shows a single "no reviewable changes" placeholder. Existing "no changes" empty state in `AnalysisView` covers it.
- **A level errors out.** Node turns red with hover tooltip. Other levels stay usable. "Retry" button on just that level.
- **PR head moves while reviewing.** Detected on next GitHub fetch; one-click "reload stack" banner. Existing drafts keep their `commitId` anchors.
- **Comment lands on a deleted file/line at submit.** GitHub's review API rejects it; we mark the comment as orphaned and surface a "promote to file-level" dialog. We do not try to re-anchor automatically.

## Testing

- **Unit**
  - `noise-classifier`: matrix of fixture commits × expected verdict.
  - `commit-stack`: diff slicing for first commit, merge commit, file deletion across levels.
- **Integration**
  - `routes/analyze.test.ts`: request stack on a fixture PR; assert WS emits one `levelReady` per non-noise level. Cache reload skips pipeline.
- **Frontend unit**
  - `TimelineRail`: render matrix across statuses (pending, analyzing, ready, error) and noise-collapse.
  - `stack` store: `setSelected` persists to localStorage.
  - `CommentBox`: writes `commitId` to the draft.
- **E2E (Playwright)**
  - Open a 5-commit PR fixture, walk the stack bottom→top, draft a comment at level 2, jump to level 4, return to level 2, confirm the draft persists.

## Phasing & Dependencies

- Depends on Phase 1.6 (cluster sidebar, draft review workflow) — already shipped.
- Independent of Phase 2 (analyzer sidecar). When Phase 2 lands, its enriched insights can plug into the per-level pipeline without reshaping this design.
